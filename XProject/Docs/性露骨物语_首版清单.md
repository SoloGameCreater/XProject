# 《性·露骨物语》开发清单（可迭代版 / 首版重排）

> 本文是“首版可卖体验优先”的排期与验收口径：先把**时间权衡 + 关系推进 + 私密反馈**做成闭环，再考虑大地图/背包/图鉴等“生活模拟装饰层”。

## 1. 使用说明
- 本清单用于逐步细化需求，达到“可执行阈值”后由 Codex 按清单实施。
- 状态字段统一使用：`未开始` / `进行中` / `已完成` / `阻塞`。
- 每次变更请在文末“变更记录”追加一行，保证可追溯。

## 2. 项目目标与范围（首版定稿）
### 2.1 目标（首版必须实现的体验）
- 目标：做一个“生活模拟外壳 + 关系推进为核心”的 NSFW 游戏首版闭环。
- 玩家在前 90 分钟内必须获得清晰的“我在正确路上”的确认信号（权限解锁/私密选项出现），且**不需要查攻略**。

### 2.2 首版范围（MVP）
- 1 个主角 + 2 个女性 NPC（温柔线 / 傲娇线）
- 时间切片：早 / 午 / 晚 / 夜
- 主角资源：行动点（AP）与精力（Stamina）分离
- NPC 状态：心情（Mood）/ 欲望（Desire）/ 关系阶段（Stage）
- 核心交互：点击 NPC → 行为菜单 → 结果反馈（数值/权限/阻力变化）
- 私密内容规则：**阶段权限解锁（确定性）**，禁止“低阶段概率越界”
- 存档：只存“能恢复核心体验”的字段（时间、主角资源、两 NPC 状态/阶段/关键标记）

### 2.3 首版明确降级/后置（不影响闭环则不做）
- 大地图多场景：首版可用“单场景多区域/面板切换”替代
- 背包/图鉴：首版降级为“极简礼物/道具列表（3~5个）+ 已获得列表”，不做完整系统
- 序列帧互动动画：首版只接入 **2 组**占位/复用动画跑通规则；“10 个全不同动画”后置

### 2.4 首版私密内容红线（第一版永远不做）
- 概率越界型私密（低阶段靠概率触发高亲密行为）
- 无状态成本私密（不消耗精力/不影响次日/不改变变量）
- 多 NPC 并行深度亲密、跨阶段跳跃、温柔/傲娇无差异高密度版本
- 情绪勒索型内容（以道德/内疚逼玩家做选择）
- 高制作成本但不改变玩法结果的“纯演出堆量”

### M2 核心玩法闭环（首版最重要：先把“做对就爽”落地）

- [ ] 主角资源：行动点（AP）与精力（Stamina）  
  状态：`未开始`

- [ ] “跳过时间/休息”行为  
  状态：`未开始`  
  验收：玩家能明确知道“该结束今天/还是继续”。

#### M2.2 NPC 状态模型与两条难度线（温柔/傲娇）
- [ ] NPC 状态结构：Mood / Desire / Stage / Flags

  验收：可独立更新、可被行为影响、可被存档保存。
- [ ] Stage 阶段推进（确定性权限解锁）  
  状态：`未开始`  
  验收：阶段到位 → 行为出现；阶段未到 → 行为不出现（不靠概率）。
- [ ] 温柔线规则（低摩擦、快确认，但有“深度天花板”）  
  状态：`未开始`  
  验收：前 90 分钟必出现“私密确认信号”；中后段回报不超过傲娇线。
- [ ] 傲娇线规则（严格条件 + 明确拒绝原因 + 做对必成）

## 5. 风险与回滚位点（首版）
- 风险1：私密表现资源交付延迟  
  - 缓解：先用占位动画/统一时长/统一镜头跑通闭环  
  - 回滚：关闭动画表现，仅保留文本与状态回写（但不影响权限解锁）
- 风险2：为了“剧情”不断加系统  
  - 缓解：新增需求必须替换删除现有项；只允许扩配置，不扩系统  
  - 回滚：冻结新需求一周，只做打磨与修 bug
- 风险3：存档字段膨胀导致联调地狱  
  - 缓解：首版只存最小集；扩字段必须带默认值与版本迁移  
  - 回滚：锁字段，仅增不改；复杂字段延后到 M4
